# Лавка зелий

Учебный интернет-магазин волшебных зелий. Командный проект курса RS School.

Деплой: https://isaluk.github.io/Team-project-RS/

## Что умеет приложение

- **О нас** (стартовая страница): описание проекта, избранные зелья, участники и их вклад.
- **Каталог**: поиск по названию, фильтры по категории, цене и редкости, сортировка по цене.
- **Котёл** (корзина): изменение количества, удаление, промокод, итоговая сумма, оформление заказа.
- Корзина сохраняется в `localStorage` и переживает перезагрузку страницы.
- Адаптивная вёрстка: от 380px до широких экранов.

Промокоды для проверки: `ALCHEMY10` (−10%) и `POTION20` (−20%).

## Стек

- TypeScript без фреймворков
- Vite (сборка и dev-сервер)
- Vitest (unit-тесты)
- GitHub Actions (сборка и тесты на каждый pull request, деплой на GitHub Pages)
- Husky (для автоматической настройки и запуска Git-хуков)
- Eslint и Prettier (поиск ошибок и приведение кода к общему виду)

## Структура

```
src/
├─ main.ts          точка входа: создаёт хранилище и запускает интерфейс
├─ types.ts         все типы проекта
├─ data/            товары и команда
├─ logic/           чистые функции и тесты к ним
│  ├─ cart.ts       операции с корзиной
│  ├─ totals.ts     подсчёт итогов и скидки
│  ├─ promo.ts      проверка промокода
│  ├─ filters.ts    поиск, фильтры и сортировка
│  ├─ format.ts     цена, ввод цены, склонение слов
│  └─ route.ts      разбор адреса страницы
├─ state/           хранилище состояния и localStorage
├─ ui/              компоненты и страницы
└─ styles/          стили
```

Приложение разделено на три слоя:

1. **logic** — функции, которые получают данные и возвращают результат. Они не трогают страницу, поэтому их легко тестировать.
2. **state** — одно хранилище с корзиной, фильтрами, промокодом и текущей страницей. При изменении сообщает подписчикам.
3. **ui** — функции, которые создают элементы страницы и вызывают логику в ответ на действия пользователя.

Цены хранятся в центах целыми числами (`$19.90` → `1990`), чтобы не было ошибок округления.

## Как мы работаем

- Основная ветка — `main`. В неё попадают только изменения через pull request.
- Ветки: `feature/<задача>`, `fix/<что-чиним>`, `docs/<что-описываем>`.
- Коммиты в стиле Conventional Commits: `feat:`, `fix:`, `test:`, `docs:`, `style:`, `chore:`, `ci:`.
- Каждый pull request ссылается на задачу (`Closes #12`) и проходит ревью напарника.
- Перед pull request: `npm test` и `npm run build` проходят без ошибок.
